# Диагностика атмосферы молодёжи

Веб-сервис для очной молодёжной встречи: ведущий создаёт комнату, участники подключаются по QR-коду, проходят 70 вопросов и получают личный результат. Проектор показывает только агрегированный прогресс и общий итог.

## Маршруты

- `/host` — панель ведущего, создание комнаты, QR-код и управление фазами.
- `/register` — регистрация отдельного аккаунта ведущего.
- `/login` — вход ведущего по email и паролю.
- `/account` — статус и профиль аккаунта ведущего.
- `/join?room=AB12CD` — мобильный путь участника.
- `/stage?room=AB12CD` — безопасный экран ожидания и общего прогресса.
- `/results?room=AB12CD` — вдохновляющий, затем реальный общий результат.

## Запуск

```bash
pnpm install
pnpm dev
```

Без `.env` сервис работает в demo-режиме в рамках одного браузера. Для настоящей синхронизации подключите Firebase.

## Firebase

1. Создайте проект в Firebase.
2. Включите **Anonymous Authentication** — он нужен только участникам комнат.
3. Включите **Email/Password** в Authentication → Sign-in method — он нужен ведущим.
4. Создайте **Realtime Database**.
5. Скопируйте `.env.example` в `.env` и заполните веб-конфигурацию Firebase.
6. Примените правила из `firebase-rules.json` в разделе Realtime Database → Rules.

Каждая комната хранится отдельно в `sessions/{roomId}`. Присоединение ограничено транзакцией на 30 участников, а записи участника привязаны к его анонимному Firebase UID. У каждой новой комнаты есть `workspaceId` ведущего.

Регистрация создаёт `users/{uid}` и `workspaces/{workspaceId}`. Пароли не записываются в Realtime Database: ими управляет только Firebase Authentication. Телефон хранится исключительно в `users/{uid}`.

Новый ведущий получает статус `pending`. Чтобы сразу выдать статус `active`, до регистрации добавьте в Realtime Database запись вида `invites/{КОД}`:

```json
{ "status": "active", "expiresAt": 1790000000000 }
```

После этого используйте ссылку `/register?invite=КОД`. Если `expiresAt` не нужен, его можно не указывать.

## Проверка перед публикацией

```bash
pnpm build
```

Проверьте сценарий в двух окнах: откройте `/host`, создайте комнату, затем откройте QR-ссылку в другом окне/на телефоне. До настройки Firebase demo-режим предназначен для визуальной проверки одного браузера; настоящая многопользовательская синхронизация требует Firebase.

## GitHub Pages

`vite.config.ts` использует относительный `base: './'`. После публикации настройте в GitHub Pages источник из ветки/папки с собранным `dist`.

## Визуальная система

Тёмный изумрудный фон, полупрозрачные стеклянные панели, мятный primary action, золото для вторичных акцентов и анимации из `../ANIMATION_SPEC.md`. Уважено `prefers-reduced-motion`.
