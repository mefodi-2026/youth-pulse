## Обязательный протокол облачного прогона (пока НЕ выполнен)

- Две независимые комнаты на режим: постепенный вход и одновременный вход.
- Ровно 30 отдельных анонимных Auth UID. Каждая запись должна подтверждаться
  callable и чтением собственной записи до запуска; без Admin создания гостей.
- Ведущий запускает один раз, только после серверного подтверждения 30 гостей.
- Отдельные счётчики: registered, firstQuestionReceived (live + доступный
  первый вопрос + собственная запись), firstAnswerServerConfirmed,
  secondQuestionReached, finished, errors, disconnects. UI и SDK различаются.
- После общей готовности первого вопроса ответы отправляются одновременно.
  Затем полный проход: 70 диагностических вопросов или реальный размер quiz.
- Сверка независимым чтением в staging: каждая сохранённая пара вопрос/ответ
  соответствует детерминированному тесту; индекс = числу вопросов; finished
  допустим только вместе с полным набором ответов; результаты пересчитаны.
- Не выполнять отдельную запись finished и не исправлять тестовые данные для
  получения 30/30. Ограничение 31-го проверять отдельно, остальные проходят.
- Отдельный чистый гостевой браузер Pages-сборки и мобильный viewport; реальный
  телефон отмечается отдельно. Staging-сборка того же SHA/базового пути НЕ
  выдаётся за непосредственно опубликованный Pages-клиент.
- Рабочий Pages жёстко связан с production backend: запрещены новые нагрузочные
  комнаты на нём. Для полной проверки опубликованного гостевого клиента без
  рабочей аналитики нужен согласованный изолированный способ проверки, а не
  подмена Vercel или изменение реальных исторических комнат.
- Артефакт каждого запуска: клиент SHA, backend SHA/revision, project/region/
  RTDB, комната, режим/набор, стратегия, отдельные счётчики этапов, коды ошибок.
  До такого артефакта облачный 30/30 остаётся непроверенным.
